# Adequora Writer website

Adequora Writer의 한국어 제품 소개 웹사이트입니다. 별도 런타임이나 설치 패키지 없이 정적 호스팅에서 제공할 수 있습니다.

## 페이지

- `index.html`: 제품 소개, 문서 구성 예시, 미디어 체험, 활용 사례, 샘플 문서.
- `download.html`: Microsoft Store 출시 예정 상태와 시스템 환경 안내.
- `guide.html`: 시작하기, 편집, 미디어, 저장과 작업 이어하기, 비밀번호, 설정.
- `support.html`: 이메일 문의, 검색 가능한 FAQ, 오류 제보 안내.
- `privacy.html`: 이 웹사이트의 개인정보 관련 안내. 앱의 개인정보 안내와는 별개입니다.

## 로컬에서 보기

파일 탐색기에서 `index.html`을 열어도 됩니다. 미디어·다운로드·클립보드를 포함한 검증에는 로컬 서버를 권장합니다.

```sh
npm run dev
```

브라우저에서 `http://127.0.0.1:4173`을 엽니다. 개발 서버의 포트는 `PORT` 환경 변수로 바꿀 수 있습니다. npm 의존성 설치는 필요하지 않습니다.

## 콘텐츠 수정

- `src/pages.mjs`: 각 페이지의 본문과 구성.
- `src/components.mjs`: 공통 메뉴·푸터·아이콘·FAQ.
- `src/config.mjs`: 문의 주소, 공개 Store URL, 샘플 문서 경로.
- `assets/style.css`: 반응형 스타일.
- `assets/site.js`: 메뉴, 탭, FAQ 검색, 주소 복사, 가이드 목차.

소스를 수정한 뒤 HTML을 다시 생성합니다.

```sh
npm run build
npm run check
```

`build`는 루트의 HTML 5개를 생성합니다. `docs`의 원본 ADQ와 HTML 파일은 수정하지 않습니다. 생성된 HTML을 직접 수정하면 다음 빌드에서 덮어쓰므로 본문은 `src`에서 수정해주세요.

## Microsoft Store 공개 시

현재 공개 Store 주소가 없으므로 출시 예정 상태를 표시합니다. 무료·유료·출시일·공개 버전은 임의로 기재하지 않았습니다.

1. `src/config.mjs`의 `storeUrl`에 실제 공식 HTTPS 제품 페이지 주소를 입력합니다.
2. `src/components.mjs`의 FAQ 중 다운로드·가격·출시일 항목과 `src/pages.mjs`의 출시 안내 문구를 확정 정보로 변경합니다.
3. 다운로드 페이지의 시스템 요구 사항과 공개 버전·업데이트 내역을 확인합니다.
4. `npm run build`와 `npm run check`를 실행합니다.

Store URL이 설정되면 다운로드 페이지의 버튼은 해당 주소로 연결됩니다. 출시 준비 문구가 다른 콘텐츠에 남아 있지 않은지도 함께 검토해주세요.

## 정적 호스팅

현재 결과는 로컬 폴더에 구현되어 있으며 외부 배포는 실행하지 않았습니다. GitHub Pages 등에서는 루트의 HTML 파일, `assets/`, `docs/`, `.nojekyll`을 상대 경로 그대로 제공하면 됩니다. 도메인이나 저장소 하위 경로를 하드코딩하지 않았습니다.

배포에 `src/`, `scripts/`, `.qa/`는 필요하지 않습니다. `.qa/`는 Git 추적 제외 대상입니다. GitHub Pages의 원본 위치로 `docs/`를 선택하지 마세요. 현재 웹사이트의 진입점은 저장소 루트의 `index.html`입니다.

## 자료와 용량

- 앱 아이콘은 제공된 Adequora Writer 소스의 아이콘을 웹용으로 최적화했습니다.
- 체험용 이미지·MP3·MP4는 `docs`의 현재 샘플 HTML에 포함된 제공 미디어에서 추출했습니다.
- 표지의 편집 화면은 실제 앱 스크린샷이 아니라 샘플 자료를 이용해 구성한 예시이며, 화면 아래에 이를 표시합니다.
- 기존 `.adq` 문서(약 17.8MB)와 독립형 HTML 미리보기(약 24.4MB)는 원본 파일 그대로 연결합니다.
- 영상은 탭 선택 시에만 로드하며, 오디오와 샘플 HTML은 방문자가 요청하기 전에는 미리 다운로드하지 않습니다.
- 외부 폰트, CDN, 방문 분석, 서버 문의 양식과 추적 쿠키를 사용하지 않습니다. 이메일 문의는 사용자의 메일 앱으로 연결합니다.

## 검증

`npm run check`는 로컬 링크·앵커·파일, 페이지 제목과 메타데이터, 메뉴 활성 상태와 출시 전 상태를 검사합니다.

이미 Playwright와 Microsoft Edge가 설치된 개발 환경에서는 아래 명령으로 브라우저 검사를 실행할 수 있습니다.

```sh
python scripts/qa.py
```

로컬 서버가 실행 중이어야 합니다. 브라우저 검사는 5개 페이지를 1440·768·390·320px에서 확인하고 탭·키보드, 오디오·영상 재생과 탭 전환 시 정지, 샘플 미리보기와 다운로드 무결성, FAQ 검색·초기화, 모바일 메뉴, 가이드 앵커를 검사합니다. 클립보드 성공·실패 처리는 브라우저의 Clipboard API를 대체하여 확인하며, OS 클립보드 권한과 메일 앱의 실제 전송은 별도 사용자 환경에 따릅니다.
